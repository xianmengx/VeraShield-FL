# Crypto-VL 客户端验证边界修复

本记录补充此前整数聚合分子修复，不将历史训练结果标记为本版结果。

## 修改

- `vl-proof-skip` 不再授权模型变化：仅允许收到的模型摘要与客户端本地缓存完全一致；无缓存时拒绝。
- 客户端使用本地运行配置中的任务标识，以及当前训练轮减一的证明轮次校验密码学证明；线性验证路径同步采用独立预期值。
- 记录本地已接受的训练轮次，拒绝重复、倒退轮次；服务器重设为第一轮不能覆盖已有缓存。
- 非对象证明、缺失字段和非法字段产生结构化拒绝回执；拒绝路径不再解析不可信证明轮次。
- 拒绝不会更新本地模型缓存或已接受轮次。缓存不变的回退流程使用明确的 `unchanged_cached_model` 回执原因。

## 验证

命令：

```bash
<LOCAL_VENV>/bin/python -m pytest tests/test_crypto_vl_client_numerator.py tests/test_crypto_vl.py tests/test_crypto_vl_keys.py tests/test_crypto_vl_canonical_aggregation.py tests/test_client_verifier.py tests/test_vl_precommit.py -q
```

结果：55 passed，2 条第三方弃用警告。

测试覆盖精确整数分子、模型替换、上下文不匹配、缓存父模型错误、跳过验证时替换模型、轮次重置、畸形证明，以及正常证明与未变模型回退进入训练前的数据加载边界。既有提交前拒绝测试覆盖连续篡改和后续恢复。

本次未启动新的完整训练或新一轮 Flower 仿真。此前四轮仿真属于前一版尺度修复的记录，不作为本次边界修复的运行证据。

## 边界

无证明的回退仅允许本地缓存不变，不能让落后客户端未经证明跳转至新的全局模型；重新加入的客户端需要单独设计经过认证的状态同步流程。

当前修改属于逻辑原型验证强化，不构成物理双服务器隐私隔离或完整密态协议的安全证明。历史多 seed 数据和冻结代码哈希未改写。
